# 1. Executive Summary

Filterzyme (packaged as `filterzyme`, shipped from the `StructureZyme` repository) is a structural-filtering pipeline that ranks ML-predicted enzyme variants for experimental validation. It chains structure prediction (Chai-1, Boltz-2), physics-based docking (AutoDock Vina via the external `docko` package), active-site prediction (Squidly LSTM over ESM2), pairwise structure superposition (biotite), and a battery of geometric / interaction scorers (fpocket, FreeSASA, PLIP) into three sequential stages â Docking, Superimposition, GeometricFilters â composed via overloaded `<<` and `>>` operators. The result is a per-enzyme DataFrame of structural features intended as a filter ahead of wet-lab assays.

The codebase is research-grade: the science is ambitious and broadly sound, but reproducibility, robustness, and code hygiene are weak. There are two divergent top-level pipelines (`pipeline.py` and `pipeline_v2.py`) with subtly incompatible intermediate schemas; a handful of name typos that will raise `AttributeError`/`NameError` on the unhappy path; ~1,730 lines of near-duplicate geometric-filtering code across three files; dead PLACER scaffolding wired to nothing; hard-coded `/nvme2/helen/...` paths in benchmarks and the README; and a smoke-test file (`test_pipeline.py`) that imports a long-renamed package (`filtering_pipeline`).

## Top 5 critical findings

1. **Two divergent pipeline entry points.** `pipeline.py` (390 lines) and `pipeline_v2.py` (410 lines) are siblings, not versions. `pipeline_v2.py` uses `enzymetk.ActiveSitePred` and returns tuples from `_proteinRMSD` / `_ligandRMSD`; `pipeline.py` uses the local `filterzyme.steps.predict_catalyticsite_step.ActiveSitePred` (a `subprocess` wrapper around a conda env) and returns single DataFrames. The README example imports `from filterzyme.pipeline import Pipeline` (i.e. v1), but the benchmarking scripts also import `filterzyme.pipeline` (v1) â yet v2 is the better-instrumented file. The two have **different intermediate-DataFrame schemas** (`label` / `Squidly_CR_Position` in v1 vs `id` / `residues` in v2 at `pipeline.py:80-83` and `pipeline_v2.py:86-89`), so they are not drop-in interchangeable.

2. **Two name typos that will crash the unhappy path.** `pipeline.py:151` and `pipeline.py:154` read `self.alternative_strucuture_for_vina` (sic â `strucuture`). The attribute is actually `alternative_structure_for_vina` (set at `pipeline.py:50`). Only `pipeline_v2.py` is spelled correctly. The typo is reachable only when `metagenomic_enzymes == 1`, so it has likely escaped notice â but it is an `AttributeError` waiting for the first metagenomic run. Independently, `setup.py:50` reads `ppython_requires=">=3.10"` (sic â leading `p`), so the Python-version floor is silently ignored by setuptools.

3. **`utils/helpers.py:add_metrics` references undefined symbols.** `helpers.py:251` references `dict_columns` and `helpers.py:264` references `extract_vina_index` â neither is defined anywhere in the module (the function defines local helpers `extract_structure_id` and `extract_index` instead). Calling `add_metrics(...)` raises `NameError` at runtime. The function is imported by `pipeline_v2.py:11`. The closely related (and working) function `extract_docking_metrics` lives just below at `helpers.py:277` â the two were probably mid-refactor.

4. **No input validation, no checkpointing, no resume.** Required input columns (`Entry`, `Sequence`, `substrate_name`, `substrate_smiles`, `substrate_moiety`, plus optional cofactor columns) are documented in the README but never validated. A failure two hours into a Vina sweep forces a restart from stage zero. Stage outputs are pickled to disk but never consulted as caches.

5. **Dead code in production paths.** `filterzyme/steps/PLACER_step.py`, `PLACER_forChai_step.py`, and `PLACER_forVina_step.py` define three `PLACER(Step)` classes, none of which is imported by either pipeline. `submit_pipeline.sh:16` invokes `run_pipeline_on_multiple_substrates.py`, which does not exist in the repo. `test_pipeline.py:5-8` imports `filtering_pipeline.pipeline` â a long-renamed package â and so will fail on any Python interpreter. `.DS_Store` is checked in at `filterzyme/squidly_final_models/.DS_Store`.

Net: the pipeline is plausibly correct on the happy path for the one or two substrates it was developed against, but it is not production-ready. Phase 0 (repo hygiene) and Phase 1 (critical bug fixes) of the roadmap in `10_roadmap.md` should be done before any external user is pointed at the package.
